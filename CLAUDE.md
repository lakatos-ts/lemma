# CLAUDE.md

`@lakatos/lemma`: the Lemma annotation language and its reference implementation. Charter: no runtime code (that is pabst's), no in-repo dependency; it owns the `typescript` dependency, the typecheck gate, and the parser bridge (`src/estree.ts`, `src/strip-types.ts`) because every consumer needs them. The `lemma` bin (`src/cli.ts`) prints a checked-program document per file (`src/document.ts`); `schemas/lemma-document.schema.json` pins it and `schemas/tarski-estree.schema.json` the ESTree inside it, which the Lean decoder in thales's `Tarski/` is written to. The one piece of engine code here is thales's emitter (`src/emission.ts`, `emission-ast.ts`, `readings.ts`, `module-graph.ts`): document v1 carries its output as `emission` beside each annotation's outcome, pinned by `schemas/thales-emission.schema.json`, until the engine-neutral document moves that lowering into Lean (the umbrella's `docs/design/repo-split.md`). Its invariants are thales's contract with it and are listed in thales's `CLAUDE.md`; thales's own fixtures and corpus pin its output from its `tests/emission-corpus.test.ts`, against the release it pins. A change to either schema is a change to the seam: bump `SCHEMA_VERSION` when a reader of an older document would misread a newer one. `tests/fixtures/` holds the bridge's goldens, of which thales keeps copies that nothing checks against these; `tests/fixtures/emission/` holds the copies of thales fixtures the emitter's unit tests read.

`src/index.ts` is the only export (`"."` in `package.json`); a name reaches an engine or the CLI by being added there, and `exports` refuses any other route in. `spec/` is the language: change `grammar.ebnf` and `semantics.md` with the parser, and add a fixture under `spec/fixtures/` for every accepted or rejected form (membership is the expectation; `spec/fixtures/README.md` explains the four corpora). `tests/` may reach lemma internals; `tests/package.test.ts` pins the published package's shape; `tests/helpers/` holds what they share.

`npm run build` emits `dist/` (the bin suites spawn `dist/cli.js`, so vitest's global setup builds first); `npm run typecheck`, `npm test`, `npm run format:check`, and `npm run coverage` are the local gate, and CI (`.github/workflows/ci.yml`) runs the same. The coverage thresholds in `vitest.config.ts` ratchet up on local runs and are only enforced in CI. A release is `npm publish` of a tagged version; thales pins it exactly (`Tarski/Lemma.lean`'s `version`) and pabst by range, so a breaking document change bumps `SCHEMA_VERSION` and the minor version together. GitHub Issues on `lakatos-ts/lemma` is the tracker. A clean rebuild is `rm -rf dist`.
